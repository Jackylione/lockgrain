# lockgrain 中文讲解

一句话用途：用一条本地命令阅读两份 `uv.lock` 的字段变化，去掉明确无序集合的排序噪声。

## 为什么做

更新依赖时，锁文件里可能同时出现 wheel 长行、marker 重排、extras 重排。
普通文本 diff 很难快速回答“到底改了哪个字段”。已有工具能汇总包版本和风险信号，
但不一定展示依赖 marker、项目元数据、顶层设置等全部字段。

这次只比较三个候选，选择了这个可离线解决的阅读问题。
[选题文档](problem.md) 保存三位不同用户在 2026-07-30、2026-09-26、2026-09-28 发布的原话，
并列出现有工具版本、上游已缓解的情况和不计入门槛的旧帖。

## 安装与最小示例

准备 Python 3.11 或更新版本即可，没有 pip 依赖。
直接保留本目录中的 `lockgrain.py`，也可将这个单文件复制到自己的项目。

```sh
python3 lockgrain.py examples/before.lock examples/after.lock
```

输出：

```text
- package["corelib"].wheels[url="https://example.test/corelib-1.0.0.whl"].hash = "sha256:old"
+ package["corelib"].wheels[url="https://example.test/corelib-1.0.0.whl"].hash = "sha256:new"
```

示例还改变了 markers 和 extras 的顺序，但这些排序变化不会出现在报告里。
示例中的 URL、包名、哈希是演示数据，不能拿去安装依赖。
比较自己的文件：

```sh
python3 lockgrain.py saved-before.lock uv.lock
```

Windows 可用 `py -3 lockgrain.py ...`。Unix 可选择给脚本加执行权限后直接执行。
文件名含空格时加引号，以 `-` 开头的文件名放在 `--` 后面。

## 怎么理解结果

`-` 是旧值，`+` 是新值。每行都有包和字段路径，新增或删除只出现一行。
相同名称的多个包会用版本和来源进一步区分；不会只留下最后一条。
同名依赖有多条时用排序后的 occurrence 编号保留各条记录。

退出码 0 表示按本工具的比较规则没有字段差异；1 表示比较成功且有差异；
2 表示输入或用法错误。**退出 1 是正常的“发现变化”，不是程序崩溃。**
工具只读两个明确传入的文件，不改写输入，不执行 uv、Git 或项目代码，不登录、不联网。

内部过程是：解析 TOML → 校验比较必需的结构 → 在明确的位置归一化无序集合 → 按字段路径比较。
它不会把所有数组都排序。顶层及包内 `resolution-markers`、wheel 记录、已知依赖集合、
`metadata.requires-dist` 里的 extras 有专门规则；其他数组保留顺序。
完整位置表在 [英文 README](../README.md#exactly-what-ordering-is-ignored)。

## 限制

只支持 UTF-8 的 uv.lock format version 1；每个文件最多 16 MiB（含边界），要求普通文件。
不接收 stdin 或 FIFO，不合并锁文件，不支持其他包管理器，也不连接 GitHub。
需要在比较期间保持输入稳定，读取过程不提供并发写入快照。

它不会判断两个 marker 表达式是否逻辑等价，也不会把 `>=3.3` 与 `>=3.3.0` 自动视为相同。
未知字段不会被丢弃，未知数组顺序改变仍会报告，因此可能保留一些噪声。
重复依赖按排序序号配对，增加同名条目时可能多显示几行；大量包升级仍可能输出很长的报告。

“没有字段变化”不等于锁文件合法、可安装、安全或未被篡改；这只是两份输入的比较结果。
结构检查覆盖比较所需的部分，不替代 uv 的完整校验。
本次实际测试环境为 Linux / Python 3.14.4，未实际执行 Windows、macOS 或其他 Python 版本。

## 开发与验证

```sh
python3 -B -m unittest discover -s tests -v
```

测试通过独立子进程执行真实 CLI，同时检查输入字节没有改变。
每条新行为都先观察失败，再写最小实现到通过，记录见 [TDD 文档](tdd.md)。
测试临时文件只创建在当前项目的 `.test-tmp/`，不用第三方依赖和网络。

自评：值得作为一个范围很小的离线阅读工具公开，但差异化价值是字段可见性和明确的排序规则，
不应宣传成全新的依赖审计能力。是否发布由林峰决定，本次仅本地交付。
